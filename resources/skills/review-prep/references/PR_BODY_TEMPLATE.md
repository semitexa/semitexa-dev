# PR Body Template

Use this structure when creating or updating PRs.

## Summary
- What the branch changes in one to three factual bullets.

## Changes
- Prefer commit subjects first.
- If commit subjects are noisy or too generic, summarize the changed areas from the diff.

## Checks
- List only the checks that actually ran.
- If a repo has no meaningful automated checks, say that explicitly.

## What to Review
- Point reviewers at the highest-risk files, flows, or behavior changes.

## What to Verify
- Mention concrete pages, commands, or scenarios worth smoke-checking.
